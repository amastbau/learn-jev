01 · The request

One state.
Several questions.

Request body
{
  "state": "My order arrived damaged.
            Can I get my money back today?",
  "model": "jev-latest",
  "questions": {
    "refund_requested": {
      "type": "noul",
      "instructions": "Is the customer asking for a refund?"
    },
    "urgent": {
      "type": "noul",
      "instructions": "Does the customer express urgency?"
    }
  }
}

The evidence

Instructions

The judgment

Each named question asks one specific thing about that same state.

02 · Noul

A yes/no question returns a probability of yes.

“Is the customer asking for a refund?” is evaluated against the message in state.

A Noul value is about whether the proposition is true. It is not a measure of intensity, and Noul has no separate confidence field.

answers.refund_requested.noul
0.93

08 · What to remember

Typed answers make routing easier.
They still need evaluation.

01

One clear judgment

Separate independent conditions so each answer is meaningful.

02

Probability ≠ proof

Test Jev's estimates on your own tasks before setting action thresholds.

03

Code stays in control

Use Jev to choose among defined options; use tools and other models for the work they fit.
